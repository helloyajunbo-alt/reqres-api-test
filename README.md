# ReqRes 接口自动化测试（pytest + requests）

ReqRes 用户管理模块的接口自动化实现。与作品集中 Postman 手工验证的 26 条用例（RQ-01 ~ RQ-26）为**同一批用例的两套实现**：Postman 用于设计验证与手工回归，本仓库用于持续集成。两套实现共用同一套用例编号，便于对照。

本项目面向接口测试岗位作品集，重点不在"跑通"，而在**分层设计、契约校验、缺陷发现与持续集成**四件事。


## 二、快速开始

```bash
# 1. 创建虚拟环境
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 2. 安装依赖
pip install -r requirements.txt

# 3. 跑真实接口（默认指向 https://reqres.in/api）
pytest

# 4. 只跑冒烟（提交前用，请求量最小）
pytest -m smoke

# 5. 查看报告
open reports/report.html           # macOS
```

离线自检（无网络或公共演示环境配额耗尽时）：

```bash
python3 mock_server.py &                                  # 启动本地替身
REQRES_BASE_URL=http://127.0.0.1:8765/api pytest -q       # 指向替身
```

## 四、断言的四层设计

| 层级 | 校验内容 | 失败意味着 |
| --- | --- | --- |
| 通信层 | HTTP 状态码、响应耗时 | 接口不可用或性能劣化 |
| 结构层 | 响应体 JSON 结构、字段是否存在（jsonschema） | 返回结构变更，前端会崩 |
| 类型层 | 字段类型、格式、长度（pattern / format） | 契约不一致，联调返工 |
| 语义层 | 业务含义：id 是否一致、页码是否被篡改、总页数是否自洽 | 接口"通"但结果错，最隐蔽 |

只写前三层，会把"返回了错误的用户"判成通过；只写第一层，等于只验证了接口没挂。

## 五、已知缺陷与 xfail 策略

三个缺陷由用例实测发现，用 `xfail(strict=True)` 钉住：缺陷被修复时用例会 XPASS 并判失败，提示同步更新用例与缺陷单，而不是悄悄通过。

| 编号 | 缺陷 | 预期 | 实际 |
| --- | --- | --- | --- |
| D-01 | 密码错误仍登录成功并下发令牌 | 400 | 200 + token |
| D-02 | 创建用户缺必填字段仍创建成功 | 400 | 201 + id |
| D-03 | 未携带令牌仍返回完整用户数据 | 401 | 200 + data |
| D-04（对照） | 篡改令牌被正确拒绝 | 401 | 401 |

D-03 与 D-04 的对照说明了一条判断：该服务的鉴权链条只校验"令牌是否合法"，没有校验"是否必须携带"。

## 六、设计取舍（面试可直接复述）

1. **接口层不做断言**。封装里判断过的用例，报告上看不出测了什么；断言全部留在用例层，失败时一眼定位。
2. **令牌用 session 级 fixture，登录一次全局复用**。既减少请求（公共环境有配额），也避免每条用例自己登录取 token 造成的前置失败级联。
3. **用 jsonschema 校验结构，不逐字段写 assert**。字段增删时改契约文件即可，用例不动——这是契约测试与字段断言的差别。
4. **参数化代替复制粘贴**。创建用例用 4 组数据共用一份脚本，新增数据只改 JSON，不加用例。
5. **限流退避放在接口层**。公共演示环境会返回 429，退避重试三次；但"重试"只解决频率问题，不掩盖功能缺陷，因此 429 之后若仍失败，判失败而不判通过。
6. **不做的事**：不做并发压测（公共服务的压测结果无参考意义）；不封装多环境切换（一层 api 足够，过度设计是减分项）。

## 七、持续集成

`.github/workflows/api-test.yml` 配置为：每次 push 与每日 09:00 定时执行，跑全量用例并上传 HTML 报告为 artifact。公共环境有配额限制，CI 里建议只跑 `-m smoke`，避免每日额度被耗尽。

如需提高配额，可在 reqres.in 免费注册获取个人 key，并设置环境变量：

```bash
export REQRES_API_KEY=你的key
```

客户端会自动在请求头附加 `x-api-key`。
